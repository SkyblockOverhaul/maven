Events

Events work like the DOM: they bubble from the deepest element to body, and stopPropagation() / preventDefault() behave as you expect.

#Handling events

button(onClick = { e -> e.stopPropagation(); join() }) { +"Join" }
div(onMouseEnter = { hovered = true }, onMouseLeave = { hovered = false }) { … }
input(onKeyDown = { e -> if (e.key == "Enter") submit() })
scroll(onScroll = { e -> atBottom = e.scrollTop >= maxScroll })
  • e.target is the element the event happened on, e.currentTarget the one whose handler runs.
  • mouseenter / mouseleave, focus / blur and scroll don't bubble; everything else does.
  • Document-wide listeners: useDocumentEvent("keydown") { … } (runs before element handlers).

#Keyboard

key uses DOM names: "a", "Enter", "Escape", "ArrowUp", "Tab", "Backspace", "Delete", "Home", "End", "PageUp", " " …. Keyboard events go to the focused element, or to body when nothing is focused.

useDocumentEvent("keydown") { e ->
    e as KeyboardEvent
    if (e.ctrlKey && e.key == "f") { searchRef.current?.focus(); e.preventDefault() }
}

#Default actions

preventDefault() onEffect
mousedownThe element is not focused.
wheelThe scroll container doesn't scroll.
keydown (Escape)The screen stays open.
keydown (Enter / Space on a button)The button isn't clicked.

The wheel scrolls the nearest scroll container; Shift + wheel scrolls sideways. A container that can only scroll horizontally also takes the plain wheel (unlike the web) and hands it on once it reaches its end.

#Focus

  • Inputs, textareas, buttons, selects and elements with tabIndex are focusable. Tab / Shift+Tab move the focus.
  • Clicking focuses the nearest focusable element; style it with :focus, :focus-visible (only keyboard focus, like browsers) or :focus-within.
  • The first Escape blurs a focused input; the next closes the screen (unless something called preventDefault()).
  • Use autoFocus = true on an input to focus it when it appears, or ref.current?.focus().
